# 확성기 수집 (Turing Amplifier — Collect)

튜링 슬랙에서 **📣 (`:mega:`)** 리액션이 달린 메시지를 찾아 Notion `📣 확성기 수집함` DB에 적재한다.
매 평일 오전 자동 실행되며, 사용자가 직접 요청할 수도 있다.

이 스킬은 **슬랙에 아무것도 쓰지 않는다.** 읽기 + Notion 쓰기만 한다. 발행은 `amplifier-weekly` 스킬이 담당한다.

## 커넥터 연결 주의

실행 시작 직후에는 Slack/Notion 커넥터가 아직 핸드셰이크 중일 수 있다. 첫 호출이 인증/연결 오류로 실패해도 곧바로 실패로 보고하지 말고, **10초 대기 후 최대 3회까지 재시도**한 뒤에 판단한다.

## 단계

### 1. 수집 창(window) — 날짜 필터를 걸지 않는다

**`after:` / `before:` 를 쓰지 마라.** `has::mega:` 만으로 전체 기간을 검색한다.

이유: 슬랙 검색의 날짜 필터는 **메시지가 쓰인 날짜**에 걸린다. 그런데 📣는 언제든 찍힐 수 있다. 한 달 전 메시지에 오늘 📣를 찍으면, 날짜 창을 걸어둔 검색은 그걸 영영 못 잡는다. 실제로 초기 8일 창 때문에 이번 주에 📣가 찍힌 8/28·9/2 메시지 두 건이 통째로 누락된 적이 있다.

슬랙 API로는 **리액션이 언제 달렸는지 알 수 없다.** 그래서 "언제 📣가 찍혔는가"의 대용으로 **`수집일시`(= 이 DB에 처음 들어온 시각)** 를 쓴다. 매 평일 수집이 돌기 때문에, 새로 나타난 건 = 최근에 찍힌 건이다.

전체 검색은 결과가 많아질 수 있으니 **커서로 끝까지 페이지를 넘기고**, 중복은 3단계에서 걸러낸다. 이미 DB에 있는 건은 `수집일시`를 덮어쓰지 않는다 — 그 값이 곧 "언제 찍혔나"의 기록이다.

### 2. 📣가 달린 메시지 검색

`slack_search_public_and_private` 를 다음 파라미터로 호출한다.

- `query`: `has::mega:` (날짜 필터 없음 — 1단계 참조)
- `channel_types`: `public_channel,private_channel` — **`im`, `mpim`은 절대 넣지 않는다.** 개인 DM·그룹 DM은 수집 대상이 아니다.
- `include_bots`: `true` (배포 알림 등 봇 메시지에도 📣를 찍을 수 있다)
- `sort`: `timestamp`, `limit`: `20`

결과가 20건이고 `next_cursor`가 있으면 **커서로 끝까지 페이지를 넘긴다.** 한 페이지만 보고 끝내지 말 것.

각 결과에서 `channel_id`, `message_ts`, 작성자, 채널명, 본문, 작성 시각을 확보한다.

### 3. 퍼머링크 만들고 중복 걸러내기

**검색 결과에 `Permalink` 필드가 들어 있으면 그 값을 그대로 쓴다.** 스레드 답글의 `?thread_ts=…&cid=…` 파라미터까지 들어 있어 클릭하면 스레드가 바로 열리기 때문에, 직접 조립한 링크보다 낫다.

Permalink가 없을 때만 다음 규칙으로 조립한다.

```
https://team-turing-workspace.slack.com/archives/<channel_id>/p<message_ts에서 점을 제거한 값>
```

예) `channel_id=C016GTMN3HN`, `ts=1786098501.466119` → `.../archives/C016GTMN3HN/p1786098501466119`

중복 판별은 `?` 앞부분(`/archives/<channel_id>/p<ts>`)으로 비교한다. 쿼리 파라미터 유무 때문에 같은 메시지가 두 번 들어가지 않게 한다.

그 다음 `notion-query-data-sources`로 수집함 DB를 조회해 **이미 있는 `메시지링크` 집합**을 가져오고, 겹치는 건은 이번 실행에서 건너뛴다. 이미 등록된 건의 내용을 덮어쓰지 않는다 — 단, 이미 있는 건이라도 `찍은사람`이 늘었으면 그 속성만 갱신한다.

### 4. 📣가 실제로 붙어 있는지 확인 + 찍은 사람 파악

신규 후보마다 `slack_get_reactions(channel_id, message_ts)`를 호출한다.

- 응답에 `mega`가 **없으면 수집하지 않는다.** 검색 인덱스가 오래돼서 이미 이모지가 제거된 메시지가 잡힐 수 있는데, **📣 제거 = 수집 취소**가 규칙이다.
- `mega` 리액션의 사용자 목록을 `찍은사람`에 기록한다 (표시 이름, 쉼표 구분).

이미 Notion에 있는 건에 대해서도 이 확인을 돌려, 📣가 사라졌고 아직 `발행됨`이 아니라면 상태를 `제외`로 바꾸고 이유를 남긴다.

**확성기봇이 발행한 위클리 본문 자체에 📣가 찍힌 경우는 수집하지 않는다.** 발행물이 다음 호에 다시 실리는 자기참조가 된다. 채널이 발행 채널(`C016GTMN3HN`)이고 본문이 `📣 튜링 위클리`로 시작하면 건너뛴다.

### 5. 맥락 채우기

- 검색에 잡힌 메시지가 **스레드 답글**이거나 **답글이 달린 부모**라면 `slack_read_thread`로 스레드를 읽어 맥락을 파악한다.
- 답글에 📣가 찍힌 경우: 저장하는 링크는 **찍힌 그 답글**의 퍼머링크로 하되, `원문`에는 부모 메시지 요지를 한 줄 앞에 덧붙인다 (`[스레드 맥락] …`).
- 본문에 `<@U…>` 형태의 멘션이 있으면 사람 이름으로 풀어 쓴다 (`slack_read_user_profile` 또는 검색 결과의 표시 이름 활용).

### 6. 제목과 카테고리 만들기

- `제목`: 읽는 사람이 클릭 없이도 무슨 일인지 알 수 있는 **한 줄 요약**(한국어, 40자 내외). "OO 공유합니다" 같은 빈 껍데기 말고 결과·숫자·변화가 드러나게 쓴다.
- `카테고리`: 아래 중 하나를 고른다.

| 카테고리 | 무엇이 들어가나 |
| --- | --- |
| 🚀 제품·개발 | 배포, 기능 오픈, 장애와 복구, 기술 결정 |
| 💰 영업·CX | 계약, 리드, 이탈, 고객 응대 이슈 |
| 📊 지표·성과 | MAU/매출/전환 등 수치, 실험 결과 |
| 🗣 고객의 목소리 | 사용자 피드백, 리뷰, 인터뷰, 컴플레인 |
| 🧭 조직·인사·총무 | 입퇴사, 제도 변경, 사무실·비품, 일정 |
| 🧩 기타 | 위 어디에도 안 맞는 것 |

애매하면 `🧩 기타`로 두고 넘어간다. 사람이 검수 때 고친다.

### 7. Notion에 적재

`notion-create-pages`로 data source `f65755db-8d88-450e-bfc0-bbfe7a37f0c3`에 신규 건을 만든다.

| 속성 | 채우는 값 |
| --- | --- |
| `제목` | 6단계의 한 줄 요약 |
| `원문` | 슬랙 본문 (스레드면 맥락 한 줄 포함). 2000자 넘으면 자른다 |
| `채널` | `#채널명` |
| `작성자` | 원문 작성자 표시 이름 |
| `찍은사람` | 📣를 찍은 사람들, 쉼표 구분 |
| `메시지링크` | 3단계의 퍼머링크 |
| `작성일시` | 원문 작성 시각 (KST, datetime) |
| `수집일시` | 실행 시각 (KST, datetime) |
| `카테고리` | 6단계의 값 |
| `상태` | `수집됨` |
| `비공개채널` | 비공개 채널 출처면 체크 |

한 번에 여러 건을 만들 때는 `pages` 배열에 모아 한 호출로 보낸다.

### 8. 지난 주 발행분 마감 처리

`상태 = 발행대기` 이면서 `발행호수`가 채워진 건 중, **작성일시가 지난 금요일 이전**인 건은 상태를 `발행됨`으로 바꾼다. (금요일에 초안을 만들 때 `발행대기`로 표시해두고, 실제 발송은 사람이 하므로 그 다음 실행에서 마감한다.)

## 출력 요약

끝나면 다음을 보고한다.

- 이번 실행에서 새로 수집한 건수, 각 건의 제목·채널·카테고리
- 중복이라 건너뛴 건수
- 📣가 제거되어 `제외` 처리한 건
- 비공개 채널 출처 건수 (검수자가 미리 알아야 한다)
- 이번 주(월~오늘) 누적 수집 건수

수집 결과가 0건이면 그렇다고 담백하게 보고한다. 숫자를 지어내지 않는다.
